Chrome HSTS Compliance:

How it is determined: Chrome requires a minimum `max-age` of 1 year (31,536,000s) to be secure. If the cache is shorter, it registers a Decay Risk. Additionally, to avoid TOFU (Trust On First Use) Risks, Chrome requires the `preload` directive in the header and submission to the preload list. Any insecure subdomain with active HSTS will trigger a Site Blocked error.
Safari HSTS Compliance:

How it is determined: Safari iOS enforces a minimum `max-age` of 1 year. Shorter durations trigger a Decay Risk. Like other browsers, if any subdomains run without SSL while `includeSubDomains` is active, the entire domain tree will experience a Site Blocked condition.
Firefox HSTS Compliance:

How it is determined: Firefox has a lower minimum threshold of 1 week (604,800s) for HSTS cache enforcement. If `max-age` is less than this, it marks a Decay Risk. It blocks cleartext subdomains if `includeSubDomains` is active, resulting in a Site Blocked status.
Edge HSTS Compliance:

How it is determined: Microsoft Edge uses Chrome's Chromium engine standards, demanding a 1-year `max-age` and preloading registration to avoid TOFU Risks. Insecure subdomains combined with strict policies result in a Site Blocked warning.

OFFICIAL LIFE-CYCLE POLICY: HSTS ENFORCEMENT

Audited Domain: enterprise-site.com

Cryptographic Compliance: Annex A.8.24 (ISO 27001:2022)

Date Generated: --

Deployment Mode: Testing (Beta)

1. Objective & Scope

To enforce TLS encryption in transit for all connections to our root namespace and subdomains, preventing credential harvesting, SSL stripping, and Man-in-the-Middle (MitM) hijackings. This policy covers all internal and external facing environments, including developer sandboxes and APIs.

2. HSTS Header Directive Configuration

All load-balancers, web services, and content delivery nodes must emit the Strict-Transport-Security header over valid HTTPS responses with the following directives:

  • Target max-age: 300 seconds
  • includeSubDomains: Mandated (All sub-assets must use SSL to prevent global domain blocking).
  • preload: Permitted ONLY after phase 4 validation is finalized.

3. Safe Rollout Lifecycle Schedule

Due to the permanent browser-caching properties of HSTS headers, deployment must proceed along the following graduated threshold phases:

  • Phase 1: Testing (Beta) - 5 Minutes max-age (Initial crawl & fallback confirmation).
  • Phase 2: Deployment (Gamma) - 1 Week max-age (Resolve mixed content anomalies).
  • Phase 3: Enforcement (Delta) - 1 Year max-age (Preloading eligibility baseline).
  • Phase 4: Preload - Submission to the browser hardcoded list.
